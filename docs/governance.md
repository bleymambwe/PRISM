# Governance

PRISM currently uses a maintainer-led governance model. Blessings Mambwe is the
project lead and release manager. Decisions affecting the public API,
scientific interpretation, security, licensing, or contributor credit should
be discussed in a public issue or pull request before release.

## Decision process

Routine fixes may be merged after maintainer review and passing CI. Significant
changes require a written rationale, alternatives considered, backward-
compatibility assessment, tests, documentation, and a changelog entry.
Scientific thresholds or claimed domain generality also require benchmark
evidence and an explicit limitations update.

If consensus is not possible, the project lead makes and records the decision.
Governance can be expanded when sustained external contributors emerge.

## Authorship and credit

Git commits acknowledge code and documentation contributions. JOSS or research
paper authorship follows substantial scholarly contribution and accountability,
not funding or general supervision alone. Reviewers and contributors who do not
meet authorship criteria should be acknowledged with their consent.

## Succession

If the lead cannot maintain the project, stewardship may transfer to an active
contributor with repository-administration access and community agreement. If
no successor exists, the final release will be archived and the repository
marked maintenance-only.
